# AI Engineer Expert Exam Guide

An English, 12-week teaching workspace for candidates preparing for the AI Engineer Expert badge shown in [`AI-Badge.png`](./AI-Badge.png).

This is an adaptive course, not a static dump of notes. It combines short explanations, retrieval practice, domain labs, scenario questions, one production-style capstone, and timed mock exams.

## Start Here

1. Read the [mission](./MISSION.md).
2. Review the [exam blueprint](./reference/exam-blueprint.html).
3. Complete [Lesson 1: Diagnostic and system map](./lessons/0001-diagnostic-and-system-map.html).
4. Keep the [12-week roadmap](./reference/twelve-week-roadmap.html) visible while studying.
5. Use the [AI engineering glossary](./reference/ai-engineering-glossary.html) when terms blur together.

## Twelve-Week Route

| Week | Focus | Primary outcome |
| ---: | --- | --- |
| 0 | Diagnostic and system map | Choose a Foundation, Core, or Accelerated route |
| 1 | Data foundations | Frame data quality, sampling, leakage, and provenance |
| 2 | ML foundations and evaluation | Select models, validation schemes, and metrics |
| 3 | Core AI and deep learning | Explain training dynamics and diagnose failure |
| 4 | Generative AI | Compare prompting, retrieval, fine-tuning, and agents |
| 5 | AI software engineering | Design stable interfaces and testable integrations |
| 6 | MLOps | Build reproducible training, tracking, and release workflows |
| 7 | LLMOps, deployment, and reliability | Operate an AI service with quality, safety, and SLO signals |
| 8 | Architecture and infrastructure | Make sound compute, storage, and serving choices |
| 9 | Performance and scalability | Find bottlenecks and plan for growth and failure |
| 10 | Responsible AI, security, and governance | Identify harms, attacks, controls, and accountability |
| 11 | Business practice and collaboration | Communicate trade-offs and defend an AI proposal |
| 12 | Mocks and targeted repair | Reach the preparation standard across all domains |

The order follows prerequisites first, then uses the image weights to distribute practice. It is not a promise that official item allocation follows this week-by-week schedule.

## Weekly Operating System

Plan for 4-5 sessions per week and 6-8 hours total:

| Session | Work |
| ---: | --- |
| 1 | One focused lesson and closed-book retrieval |
| 2 | A domain lab or code/data interpretation task |
| 3 | Scenario questions with written reasoning |
| 4 | Interleaved review and error-log repair |
| 5 | Optional capstone work or timed set |

Each lesson should end with evidence: an explanation, a design decision, a working artifact, or a corrected mistake. Learning records are created only after understanding is demonstrated.

## Readiness Standard

This workspace uses the following internal preparation standard:

- At least 80% in every domain diagnostic or review set.
- At least 85% on two complete timed mocks.
- A defensible explanation of key architecture, reliability, security, and responsible-AI trade-offs.
- A small end-to-end document-intelligence/RAG service with a classical-ML component, evaluation plan, deployment boundary, and operations plan.

These are preparation targets, not official SDAIA pass marks.

## Audience Adaptation

The shared Expert route assumes basic Python, algebra/probability, Git, and command-line use. Lesson 1 routes learners into:

- **Foundation:** repair prerequisites before advancing.
- **Core:** follow the standard lesson and lab sequence.
- **Accelerated:** spend less time on exposition and more time on scenarios, integration, and mocks.

The tools are local-first and cloud-neutral. Cloud provider mappings are optional, so credentials and cost do not block study.
